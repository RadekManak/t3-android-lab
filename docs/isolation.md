# Isolation boundary

The Android app is a client. T3's backend and provider processes run in the rootless `t3-a54-sandbox` container. The image contains the selected checkout's backend bundle, runtime dependencies, and a standalone Codex binary. Its public relay and telemetry build configuration is cleared before bundling. The checkout, its `.env` files, and source maps are not copied into the image.

The container has loopback networking only. It runs as UID 1000 with no Linux capabilities, no-new-privileges, a read-only image, a 3 GiB memory limit, and a 256-process limit. A temporary filesystem serves `/tmp`.

The writable home is the dedicated `t3-a54-sandbox-home` Podman volume. It contains the Codex login, synthetic projects, T3 state, and credentials generated by this sandbox for its own clients. Host home directories, project directories, SSH keys, GitHub credentials, cloud credentials, container-management sockets, and the live T3 database are outside the mounts.

The other mounts contain UNIX sockets only. The read-only `/egress` directory exposes a host proxy. It accepts HTTPS CONNECT requests to `chatgpt.com`, `auth.openai.com`, and `api.openai.com` on port 443. It resolves only public IP addresses and requires a matching TLS ClientHello hostname before forwarding bytes. It does not decrypt TLS, add credentials, or accept arbitrary destinations. Each bridge listener admits at most 32 concurrent connections; its host service has a 256 MiB memory limit and a 96-task limit. The container cannot bypass the proxy using a direct route. Requests to download updates, arbitrary Git remotes, and external MCP services fail under this policy. Services performed inside OpenAI remain subject to the Codex account's own permissions.

The `/ingress` directory contains the backend's UNIX socket. A host bridge bound to loopback forwards the phone's requests to this socket. It opens the socket with `O_PATH | O_NOFOLLOW`, verifies its type, and connects through the pinned descriptor. A container-controlled symlink cannot redirect this bridge to another host socket. ADB reverse carries the host loopback ports to the phone over the paired Tailscale connection.

The phone, host Metro, Android builds, and the device-control tools are outside this container boundary. Metro serves code from the selected worktree. Android permissions and the phone's own Tailscale login are separate from the credentials available to agents inside the backend container.

The owner reservation coordinates launcher operations on one device host. Other hosts require explicit coordination before using the same physical phone. Direct AgentDevice commands are governed by the project skill and the T3 device-session controls.

The container shares the host kernel. This setup restricts filesystem access, privileges, networking, and credentials; it does not provide a virtual machine boundary.

## Files excluded from Git

`config.local.json` contains sandbox addresses and executable paths. `devices.local.json` contains device addresses and availability policies. Both are ignored by Git. `.state` contains sockets, reservations, temporary image inputs, and logs. Codex authentication and T3 data live in the Podman home volume, outside the repository. Build and backend startup logs can contain pairing credentials and must remain private.

The repository deliberately excludes device screenshots, databases, auth files, ADB keys, dependency trees, native APKs, and compiled backend bundles. Rebuild artifacts on each device host.
